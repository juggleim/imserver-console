## Context

Console 后端已经提供 `GET /admingateway/apps/statistic/msgrealtime`，并通过应用配置 `open_real_time_msg_statistic` 控制 IM Server 是否采集实时统计。当前 Vue 应用只展示按天统计，无法操作开关或消费实时接口。JuggleChat Console 已有对应页面，可作为交互和数据处理参考，但两个项目在 API 前缀、配置更新参数、CSS 前缀和 i18n 命名空间上不同。

## Goals / Non-Goals

**Goals:**

- 在当前 Vue 应用中提供独立的实时消息统计入口。
- 复用现有后端接口和配置接口，支持单聊、群聊、聊天室。
- 按后端相同规则选择 30 秒至 15 分钟时间桶，补齐空桶并显示每秒平均消息数。
- 提供中英文界面、可测试的时间序列纯逻辑和已更新的嵌入式构建产物。

**Non-Goals:**

- 不修改实时统计采集、数据库表或查询 API。
- 不改造原有按天统计页面。
- 不实现 WebSocket 推送或自动轮询；“实时”表示查询细粒度的近期统计数据。
- 不恢复或修改已废弃的 `routers/admin` 静态资源。

## Decisions

1. **独立页面而不是改造三个按天统计页面。** 实时统计有不同的时间范围、纵轴语义、开关和频道切换，独立页面可避免影响已有按天统计行为。
2. **将时间桶选择、范围校验和补零逻辑放入独立 `.mjs` 模块。** 页面只处理状态和绘图，纯逻辑可以由 Node 原生测试直接覆盖。
3. **复用现有配置 API。** 页面使用 `Application.getSetting` 和目标项目既有的 `Application.updateSetting({ id, value, app_key })`，不改变共享 service 签名。
4. **时间轴使用 ECharts `time` 类型。** 返回数据按时间桶补零为 `[timestamp, value]`，避免 30 秒或分钟级数据被按日期压缩。
5. **快捷范围和页面文案归入现有 `analysis` i18n 命名空间。** 不引入参考项目的 `ui`、`data` 命名空间。
6. **构建 `webconsole/web/dist`。** Go 通过 `go:embed` 使用该目录，源码变更完成后必须生成并审阅哈希构建产物。

## Risks / Trade-offs

- [应用配置有缓存，开启后可能不会立刻产生数据] → 页面仅提示设置成功；采集生效时间保持后端现有语义。
- [没有自动轮询，页面数据不会自行刷新] → 用户可切换范围或频道触发刷新；保持与参考实现一致，避免后台持续请求。
- [自定义范围端点不一定与桶边界对齐] → 从首个完整桶开始补零，并固定图表显示的最小、最大时间为用户选择范围。
- [页面销毁后 ECharts 资源泄漏] → 在组件卸载时移除 resize 监听并调用 `dispose()`。
- [网络异常导致 Promise rejection] → 页面查询和设置操作均捕获异常并显示双语错误提示。
